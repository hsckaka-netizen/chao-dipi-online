# 房间、观战、牌桌 UI 与外观素材

## 房间与观战

- 准备阶段所有真人可准备/取消准备；全部准备后房主才能开始。
- 房主可重复添加机器人、踢出机器人、踢出其他玩家、随机座位和解散房间。
- 房主开局前可将起始叫分设置为总牌分的 10%、20%、30% 或 40%，默认 40%；房间不再提供亮 2 叫主选项。
- 房主退出时房主身份转交下一个玩家；房间仅剩机器人时自动解散。
- 准备阶段点击退出房间会从服务器玩家列表中真正移除。
- 牌局进行中按钮显示为“暂离牌桌”，保留席位、手牌和牌局身份。同一登录账号可在首页进行中房间点击“返回牌桌”恢复原玩家编号和操作权，其他账号不能冒用。
- 结束后每名玩家独立停留在自己的结算页；点击“再来一局”后只有本人进入准备页并自动准备，其他人仍可继续查看结算。刷新页面不得改变个人是否已进入下一局的状态；所有原玩家确认后才清空上局结果并进入完整准备状态。
- 进行中房间显示在首页但不可加入；登录后可点击任意玩家头像以该玩家完整视角观战。
- 观战者不能执行任何牌局操作，手牌不做特殊变色，可随时退出观战。
- 房间左下角仅在有人观战时显示观战图标和人数；点击后展示观战账号的头像、昵称和正在观看的玩家。

## 牌局内互动

- 第一期仅支持打牌阶段发送服务端预设的嘲讽词。
- 真人玩家可从手牌操作区打开面板发送；所有玩家与观战者会在发送者头像上看到约 4.5 秒气泡。
- 管理员可新增、修改、启停和删除嘲讽词，并设置所有玩家可用或只允许指定玩家账号使用。
- 已有嘲讽词的文案、启停和适用玩家支持在嘲讽词模块统一保存；新增与删除仍作为独立即时操作。
- 后台的嘲讽词新增表单和每条文案的玩家授权清单默认收起；列表摘要直接显示“所有玩家”或指定人数，只有需要调整范围时才展开账号清单。
- 玩家快照只返回本人可用文案，发送时服务端再次校验授权。
- 连续发送冷却为 1.5 秒，同一玩家的新气泡替换旧气泡。
- 发送行为不进入牌局事件或历史记录，只有文案和授权配置持久化。
- 所有真人均已登录且账号不重复时，发牌后依次进入 20 秒“重开卡阶段”和 20 秒“其他卡牌阶段”，两个阶段都可提前选择不使用/完成；全员完成时提前进入下一阶段，超时自动完成。牌局可包含 AI，含 AI 时界面明确提示使用不消耗卡片；AI 自动选择不使用，观战者只能看到阶段、全局提示和效果。
- 任何玩家使用卡牌时，所有玩家与观战者都收到包含玩家名和卡牌名的全局提示，卡牌阶段中持续列出本阶段已使用记录。
- 战神卡生效后，使用者头像周边持续显示全员可见的战神标记，直到本局结束。
- 牌运卡生效后，使用者头像左上角持续显示幸运神标识；本人视角显示“牌运之神庇佑着你”，其他玩家和观战视角显示“牌运之神庇佑着他”。
- 缤纷卡生效时，道具弹窗、炒底牌桌中央和炒底选择弹窗持续展示本局花色 2 由大到小的新顺序；重开卡生效后旧局作废并重发。

## 牌桌布局与交互

- 每个玩家看到自己位于牌桌底部，但其他人的逆时针顺序保持不变。
- 玩家卡片分布在牌桌四边；牌朝向始终正立，出牌区朝向圆心且不得互相遮挡。
- 玩家卡片以方形大头像为主要视觉区域；身份区需为外扩头像框预留宽度和头像—昵称安全间距，头像框不得与用户名重叠；鼠标移入头像或触屏点击聚焦时，才通过头像底部灰色蒙层展示历史总局数和总积分。
- 本局牌分、被拖红方五和甩失保持底部单行。
- 本人手牌框铺满牌桌可用宽度，尽量与侧边第二排玩家保持小间距并减少牌桌总高度。
- 叫分和炒底打出的牌或分数显示在对应玩家朝向牌桌中心的出牌区，不放在玩家卡片上方。
- 牌桌中心状态只用简短文字行展示必要事实和当前可操作项，不使用信息卡片，不重复展示服务端阶段长句。
- 手牌与牌桌合并，尽量减少滚动；牌可重叠，但左上角点数和花色必须可见。
- 已选手牌可通过点击页面任意非交互区域收起；牌、按钮、输入控件和链接不触发清空。
- 移动端支持点击与滑动选牌；非自己回合也可预选，轮到后直接出牌。
- 跟牌阶段的选牌数显示为“已选数量/本轮需跟数量”；达到需跟数量后不能再继续选牌。
- 首家所出一路在本人手中不多于需跟数量时，该路现有手牌在进入跟牌选择后默认选中；数量不足时，玩家再补足其他牌。
- 房主的重开房间和解散房间操作放在牌桌区域之外、牌桌卡片正上方，执行前必须通过二次确认弹窗。
- 桌面端顶部玩家的出牌区从头像左侧向右延伸；左右侧玩家的出牌区从靠近头像的一侧向牌桌中心延伸，不随内容数量居中。正式出牌、炒底亮出的 2 和叫分信息统一遵循该方向。出牌未超过横向可用范围时保持单行；超过后自动折行，折行之间允许上下部分重叠以减少纵向占用，但每张牌左上角的点数和花色必须完整可见。
- 左右侧玩家一次打出多张牌时使用更宽的自适应展开间距；不同牌数可分级收紧，但每张牌的左上角点数和花色必须可辨认。
- 当前回合、当前最大和轮到自己必须有明确但互不冲突的视觉状态。

## 头像与特效

- 账号的头像框与牌面边框是两个独立字段；选择其中一个不得自动修改另一个。
- 头像框和牌面边框作为永久皮肤通过钻石商城购买或由管理员直接发放；玩家在“我的皮肤”中自行装备或卸下。
- 管理员不能替玩家修改当前装备，只能发放皮肤拥有权；旧用户迁移时只保留当时已装备皮肤。
- 当前头像框保留皇家蓝城邦、剧场偶像、暗黑地狱、血精灵奥术、冰雪熔炉、7号传奇、圣光骑士、至尊星耀 VIP、魔兽七职业，以及小黄人工坊、乌萨奇萌兔、玩具总动员；经典 VIP、翡翠、紫晶和冠军头像框下架。
- 牌面边框仍独立保留翡翠、紫晶、冠军及既有主题，不因同名头像框下架而删除。
- 至尊星耀 VIP 头像框使用静态 PNG，并只由界面增加低频、低亮度环境光；牌面边框固定使用静态 SVG，不持续闪烁。
- 自定义头像嵌入方形素材中央开口；头像框不得被父容器裁断或遮挡昵称。
- 头像框始终位于头像图片之上，头像图片尺寸不因是否装备头像框而变化。
- 房间玩家列表、首页房间列表、牌桌玩家卡片、本人手牌区和管理页均必须允许框体外扩完整显示，只裁切昵称文字。
- 手牌和桌面出牌使用出牌者自己的牌框；观战视角保持被观战玩家的手牌样式。
- 烟花特效只在玩家一次打出至少 8 张牌且打出瞬间成为当前最大时，于该玩家出牌区域播放；甩牌按总张数计算。
- 红桃 5、方块 5 的被拖效果按每次出牌后的临时最大结果即时判断；首次确定不再是当前最大时播放一次，正式计数和积分仍在本轮结束时结算。

## 外观素材通用约束

- 头像框与牌面边框使用相同主题编号，但必须独立保存和选择。
- 主题编号只允许小写英文字母、数字和连字符。
- 同一主题可以同时提供头像框与牌框，但两类商品清单独立；职业与可爱主题允许只提供头像框。
- 未完成素材存放在 `.asset-staging/cosmetics/`；全部确认后才移入 `public/assets/cosmetics/`、加入内容版本并发布。

### 头像框

- 新头像框以 [`avatar-frame-design-spec.md`](avatar-frame-design-spec.md) 为完整设计和验收标准，并使用 `docs/assets/avatar-frame-template.svg` 起稿。
- 文件名：`avatar-frame-<theme-id>.png` 或 `avatar-frame-<theme-id>.webp`。
- 画布固定为 512×512 px、sRGB、透明背景，不得使用不透明方形底图。
- 外框所有像素必须留在画布内，建议四边至少保留 8 px 透明余量。
- 基础内开口固定为 `x=96..416、y=96..416` 的 320×320 px 正方形，五官核心安全区 `x=128..384、y=128..384` 必须完整透明；不同主题不得改变框体开口尺寸。
- 顶部体量从标准开口上沿向画布顶部和两侧发展，底部主题元素可居中或分布到左右两侧；单侧构图允许偏置，但主要体量必须朝画布外侧生长。
- 四角和上下装饰不得伸出画布；框体需形成连续闭合的视觉路径，主题元素可以替代局部实体导轨，但必须明确连接两端。
- 视觉重量集中在顶部和底部；两侧只使用 24–40 px 的窄导轨，不得做成四边等宽的厚重方框。
- 闪电、火焰、水花等局部效果必须依附主题元素，不能均匀铺满整圈或穿过头像中心。
- 单文件建议不超过 300 KB，不得带动画；透明像素必须真实透明。
- 可直接把最终图片缩小到 38、48、80、104 px 目视确认主题辨识；正方形开口、外扩和遮挡范围以固定像素坐标验收，不要求浏览器页面检查。

### 牌面边框

- 文件名：`card-frame-<theme-id>.svg`，优先使用纯矢量 SVG。
- SVG 固定使用 `viewBox="0 0 56 70"`，透明背景，按牌面宽高 100%×100% 缩放。
- 外框控制在画布内，主要边框厚度建议 1.5–2.5，内侧细线不超过 1，圆角基准半径为 6。
- 左上角 `x=5..25、y=5..34` 是点数和花色安全区；除最外侧边线外必须保持透明。
- 中央牌面必须透明，不得改变白色牌底和既有花色颜色。
- 运行时使用低饱和哑光外框和 2–3 px 左侧主题色导轨；重叠手牌通过连续可见的左边识别主题，不依赖外发光。
- 点选态沿用系统绿色轮廓，不随皮肤使用高亮光晕；普通牌面边框不得持续闪烁或呼吸。
- 右下角徽记建议限制在 `x=41..55、y=55..69`。
- SVG 不得包含脚本、动画、外链、字体或内嵌位图；渐变 ID 使用主题前缀，单文件建议不超过 24 KB。
- 必须在 50×62、56×70、62×78 px 三种牌尺寸下检查点数花色、选中描边、拖牌标记和烟花层级。

## 发布与缓存

- 素材未全部确认前，线上使用 CSS 备用框，素材文件不得提交到 GitHub。
- 全部素材确认后一次性移入正式目录，并在 `public/asset-versions.js` 中登记文件内容 SHA-256 的前 12 位。
- 前端只引用带内容版本的 URL；素材内容未变化时不得改版本，内容变化后必须更新版本。
- 发布前按本次影响范围检查桌面端、移动端、手牌、当前轮出牌、历史出牌、甩牌牌型、叫主/炒底牌和观战视角。

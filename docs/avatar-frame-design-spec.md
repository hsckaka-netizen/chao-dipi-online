# 炒地皮头像框设计与交付规范

> 版本：`2026-08-13-v11`。本规范同时约束头像框素材、管理后台验收和游戏界面叠加行为。

## 1. 核心定义

头像框是一张独立的透明前景 PNG。素材自身完成框体、徽记、装饰和必要特效的设计；除设计本体外，其他区域必须真实透明。

- 运行时头像图片在下，头像框槽位在上；未佩戴时槽位使用系统默认框，佩戴后由完整头像框素材替换，两个框不得同时显示。
- 程序不分析素材中的框体、装饰或透明区域，只按统一规则完整、等比叠加。
- 禁止为单个主题增加缩放、位移、裁切或 CSS 补偿。
- 素材不得自带头像、示例照片、方形底板或不透明背景。

现有内置头像框以最早入库的完整 PNG 为素材源，逐项记录在 [内置头像框素材映射](assets/avatar-frame-material-map.json) 中。不得再用“统一内开口”或“头像安全区”覆盖原图，也不得对顶部、底部或中间装饰做二次清除。历史原图只证明素材内容来源，不证明它天然符合本规范的标准虚拟框架；未经逐张标定前，统一标记为 `legacy-unverified`。

## 2. 固定几何规范

| 项目 | 必须规则 |
| --- | --- |
| 画布 | `512 × 512 px`、sRGB、8-bit RGBA、非隔行 PNG |
| 虚拟框架形状 | 圆角正方形；它就是头像实际裁切外沿在素材画布中的映射，不是素材可见内开口 |
| 虚拟框架尺寸 | 外接边界固定为 `x=70..442`、`y=70..442` 的 `372 × 372 px`，中心点为 `(256, 256)` |
| 虚拟框架圆角 | 源文件圆角半径固定为 `32 px`，即边长的 `32 / 372 = 8.602%`；运行时头像圆角必须按同一比例缩放，不得使用跨尺寸固定像素圆角 |
| 框体基准 | 框体主体围绕虚拟框架路径设计，可同时占据路径内外；四边形成连续闭合或由主题元素明确接续的视觉路径 |
| 向内设计 | 可从虚拟框架向头像内任意延伸；虚拟框架只负责对齐，不生成透明遮罩或裁切边界 |
| 向外设计 | 可从虚拟框架向外延伸，但必须保留画布边缘透明区 |
| 画布边缘 | 所有可见像素位于 `x/y=8..504`，四边至少 `8 px` 完全透明 |
| 文件大小 | 不超过 1.2 MB，不带动画 |

标准虚拟框架的路径从 `(102,70)` 出发，沿顶部到 `(410,70)`，以 `32 px` 半径转过四个圆角，再依次经过右、下、左四边闭合。等价 SVG 为：

```svg
<rect x="70" y="70" width="372" height="372" rx="32" ry="32" />
```

使用 [头像框坐标模板](assets/avatar-frame-template.svg) 起稿，并参考 [虚拟框架几何图](assets/avatar-frame-geometry-diagram.svg)。`GUIDES_DO_NOT_EXPORT` 只用于对齐，导出前必须隐藏。

虚拟框架是一条不导出的几何基准路径。它不是可见描边，不规定框体厚度，也不能从可见内开口反推。运行时只允许对完整 `512 × 512` 画布进行一次等比缩放：横向与纵向缩放比例必须完全相同，素材中心与头像中心始终同时位于 `(256,256)`；不得单独压缩顶部、拉长两侧、抬高底部或清除虚拟框架以内的像素。

## 3. 基本设计理念

1. **先确定头像外沿，再设计框体。** 头像外沿由标准虚拟框架唯一决定；任何可见内沿、下沿、徽章或装饰都不能反过来改变头像的位置和尺寸。
2. **框体围绕路径生长。** 主框体以虚拟框架路径为骨架，可以向路径内侧覆盖头像，也可以向路径外侧扩展；内外延伸都是完整设计的一部分。
3. **装饰从属于框体。** 徽章、人物、武器、藤蔓、火焰和粒子可以突破框体，但必须与框体有明确视觉连接，不能用孤立装饰代替整体框架。
4. **透明画布只是载体。** 除框体和装饰本身外均保持真实透明；透明区域不代表头像安全区，程序也不会利用透明区重新计算头像边界。
5. **同一几何适配所有尺寸。** 紧凑、普通、牌桌和大尺寸只缩放同一份完整画布；不允许按场景或主题设置不同位移、宽高比和裁切区域。
6. **原始素材与标准素材分开管理。** 历史素材可以作为视觉参考和来源留档，但只有经过标准虚拟框架标定的文件才能标记为 `canonical`。

## 4. 视觉设计建议

以下内容用于控制风格和辨识度，不改变前述强制几何：

- 上下承担主要设计量，两侧使用较窄的连接导轨，避免四边等宽的厚重方框。
- 武器、藤蔓、能量带、闪电或火焰可以替代局部实体导轨，但必须与两端明确连接。
- 零散粒子不能单独充当边框；向内装饰是否覆盖头像由设计本身决定。
- 顶部装饰向顶部和两侧发展；底部元素可居中，也可拆分到左下和右下。
- 数字、字母、徽记和人物主体必须保持自然纵横比，不得拉宽或压扁。
- 缩小到紧凑头像时，仍应通过轮廓、主色或独有符号识别主题。

## 5. 界面尺寸与预留区域

“头像尺寸”指头像外沿正方形，该外沿与素材中的虚拟框架完全重合；向内和向外的可见设计都只是额外覆盖，不能用来推算头像边界。“展示区”用于完整显示头像框素材。有无头像框都使用同一展示区，不得在佩戴后改变布局占位。

运行时完整展示区固定为头像尺寸的 `512 / 372 = 1.376344...` 倍。界面数值可以按子像素显示，但不得把比例改写为按主题配置。头像圆角固定为头像尺寸的 `8.602%`，与源文件 `32 px` 圆角一致。

| 界面 | 头像尺寸 | 完整展示区 |
| --- | ---: | ---: |
| 顶栏、排行榜、后台账号列表 | 38 px | 52.301 px |
| 排行榜移动端 | 34 px | 46.796 px |
| 房间列表、准备页、观战列表、普通资料区 | 48 px | 66.065 px |
| 数据详情页 | 76 px | 104.602 px |
| 牌桌其他玩家 | 80 px | 110.108 px |
| 本人手牌区桌面端 | 104 px | 143.140 px |
| 本人手牌区移动端 | 72 px | 99.097 px |
| 商城主预览 | 88 px | 121.118 px |
| 商城小预览 | 38 px | 52.301 px |

- 展示区及其父布局必须允许完整框体显示，不得裁切顶部、底部或两侧。
- 昵称、积分和操作按钮按完整展示区避让，不得仅按头像尺寸计算间距。
- 图层顺序固定为：背景 < 头像图片 < 单一头像框槽位 < 明确允许覆盖的状态标识和牌局特效。
- 头像加载完成、页面刷新或局部重绘都不得改变图层顺序。
- 桌面牌桌左右座位必须把姓名、牌分和状态放在头像外侧：左侧文字在左、右侧文字在右，靠牌桌中心的一侧留给头像和出牌区。

## 6. 后台上传与验收

- 商城和“我的头像框”只展示头像框透明素材本身，不叠加示例头像。
- 管理后台选择新 PNG 后，先展示带标准虚拟骨架辅助线的素材原图、紧凑/牌桌/大展示区纯素材缩放，以及同尺寸的真实头像叠加效果，再允许上传。
- 服务端强制校验文件格式、画布尺寸、编码、文件大小、四边透明区和至少存在一个可见像素；不检查或裁切素材内部区域。
- 连续闭合、主题辨识和是否存在无关像素由管理员通过预览人工确认。
- 校验通过后创建新头像框商品，默认为草稿；修改素材使用新的主题编号或版本，不覆盖旧资源地址。
- 上传规则用于新素材；最早入库的内置素材按素材映射中的完整文件哈希锁定，不为迎合后续上传校验而重新编码、裁边或清除内部设计。
- 自动校验只能确认文件技术规格；管理员必须勾选确认素材以标准圆角虚拟框架为骨架且真实叠加效果正确，服务端未收到确认时拒绝上传。未确认的历史素材保持 `legacy-unverified`，不能因为文件尺寸正确就标记为规范素材。

## 7. 禁止的错误解释

- 不得把可见内开口当作头像边界。
- 不得把底部或顶部装饰的内沿当作框体基准。
- 不得为了露出头像而对素材中央做矩形、圆形或任意透明遮罩。
- 不得用每个尺寸固定 `7 px` 等方式设置头像圆角；圆角必须随头像等比缩放。
- 不得因为 18 张历史素材都是 `512 × 512 px`，就推断它们天然共享同一虚拟框架。

## 8. 交付验收清单

- [ ] 头像框四边沿虚拟框架闭合，没有无承接断口。
- [ ] 虚拟框架为 `372 × 372 px`、圆角半径 `32 px` 的圆角正方形，中心为 `(256,256)`。
- [ ] 头像外沿与虚拟框架的形状、尺寸、中心点和圆角比例完全一致。
- [ ] 四边 `8 px` 全透明；虚拟框架内外的设计内容保持完整，没有矩形硬裁切。
- [ ] 没有头像、底图、棋盘格、黑底或无关半透明色块。
- [ ] 实装时头像图片始终在下，头像框始终在上。
- [ ] 系统默认框与购买头像框使用同一槽位并互相替换，没有双框叠加。
- [ ] 紧凑、普通、牌桌和大尺寸中框体都完整可见，不被父容器、昵称或头像裁切。
- [ ] 有框与无框切换时，头像大小和页面布局占位不变。
- [ ] 内置素材文件与素材映射中的最早来源和 SHA-256 一致，顶部、底部和中间设计没有经过二次遮罩。
- [ ] 历史素材只有经过逐张对齐标定后才能从 `legacy-unverified` 改为 `canonical`。

# 炒地皮头像框设计与交付规范

> 版本：`2026-08-11-v6`。本规范用于聊天生成和后台上传新的头像框素材；所有“必须”项均为上线验收项。

## 1. 核心定义

头像框是一张独立的透明前景 PNG。运行时，头像图片在下，头像框作为一整张图片直接覆盖在上。

- 素材中只有框体、徽记、装饰、阴影和必要的主题效果保留像素；其余区域必须真实透明。
- 不设“内开口”“五官安全区”或其他强制透明分区，也不按框体与头像的重叠面积做上传校验。
- 框体可自然覆盖头像的任意位置；是否遮住照片由最终框体设计决定，不能靠裁掉框体内容解决。
- 素材不得自带头像、示例照片、方形底板或不透明背景。

## 2. 交付文件

| 文件 | 要求 |
| --- | --- |
| 最终素材 | `avatar-frame-<theme-id>.png`；聊天生成后由后台上传 |
| 可编辑源文件（可选） | Figma、PSD 或 AI 任一；需要继续迭代时再提供，图层需命名并保留可编辑结构 |
| 设计说明（可选） | 主题名、`theme-id`、主色、识别符号、素材授权说明 |

## 3. 文件与透明要求

| 项目 | 规则 |
| --- | --- |
| 画布 | 固定 `512 × 512 px`、sRGB、8-bit RGBA、非隔行 PNG |
| 背景 | 整张素材使用透明背景；非框体区域 Alpha 必须为 0 |
| 外边距 | 四边各保留至少 `8 px` 完全透明，所有可见像素留在画布内 |
| 文件大小 | 不超过 1.2 MB，不带动画或多余元数据 |
| 缩放 | 始终使用完整 512 × 512 画布等比缩放；禁止为了适配页面把素材横向拉宽或纵向压扁 |

服务端会校验尺寸、PNG 编码、四边 8 px 透明和至少存在一个可见框体像素。服务端不能自动辨别“哪些像素属于框体”，因此“非框体区域真实透明、没有底图或照片”必须在人工验收中确认。

使用 [头像框坐标模板](assets/avatar-frame-template.svg) 起稿。模板中的 `GUIDES_DO_NOT_EXPORT` 图层只用于确认画布和外边距，导出前必须隐藏。

## 4. 视觉结构

推荐采用“上下有设计、两侧轻量”的结构，避免四边等宽导致头像被厚框包住。每款头像框建议包含：

1. **上下主轮廓**：顶部冠饰和底部底座承担主要设计感，缩到 38 px 时仍能看出外形。
2. **两侧连接**：只负责连接和稳定轮廓，避免两根厚重立柱抢走头像主体。
3. **主题识别点**：顶部或底部至少一个唯一符号；不能只靠换颜色区分主题。
4. **质感细节**：只服务于 80–104 px 大尺寸，不承担主要识别。

框体必须有连续、清晰的视觉路径。武器、藤蔓、能量束和局部粒子可以替代局部实体边框，但必须看得出与主体相连；零散火花不能单独充当边框。

- 视觉重量建议约 65% 放在顶部和底部，约 35% 放在左右两侧。
- 顶部和底部可以覆盖头像边缘，以完整保留徽记、数字、底座或内沿；不要把这些元素人工裁平。
- 闪电、火焰、水花、叶片等效果必须绑定明确锚点，不能均匀铺满整圈或形成不透明雾层。
- 数字、字母、徽记、徽章和人物主体必须保持自然纵横比；禁止横向拉宽、纵向压扁或透视变形。
- 必须同时考虑浅色、深色和牌桌绿色背景；禁止大面积纯白外发光、整圈霓虹、黑底或半透明方块。

## 5. 与游戏界面的关系

| 界面 | 头像基准 | 框体实际显示约 | 验收重点 |
| --- | ---: | ---: | --- |
| 房间列表、数据榜单 | 38 px | 约 50 × 55 px | 轮廓和主色可辨，昵称不被遮挡 |
| 普通资料区 | 48 px | 约 63 × 69 px | 头像仍是主体，不显得拥挤 |
| 牌桌其他玩家 | 80 px | 约 106 × 115 px | 主题有价值感，道具标记仍清楚 |
| 本人手牌区 | 104 px | 约 137 × 150 px | 细节完整，不被父容器裁切 |

- 框体在前景、头像在后景；使用实际前景图片层，不使用伪元素，也不保留旧头像边框。
- 运行时以完整的 512 × 512 px 框体画布作为唯一定位基准，完整画布固定按头像内容尺寸的 160% 显示。
- 不得依赖某一款素材的额外缩放、位移或裁切补偿；同一套前景叠加逻辑适用于所有主题。
- 头像框不得遮挡昵称；房间玩家列表、首页房间列表、牌桌玩家卡片、本人手牌区和管理页均必须允许框体外扩完整显示。

本节只说明素材的使用环境。只要素材通过第 3、6、7 节的图片检查，即可进入接入流程；主题接入未修改头像容器时，不要求重复进行浏览器尺寸调试。

## 6. 导出与上传

- 只交付静态 PNG；常规头像框不得提交 GIF 或 WebP。
- 聊天生成后直接导出 PNG，并在“钻石与商城”的“上传聊天生成头像框”中提交；后台默认创建草稿。
- 通过验证后素材存入 Storage，并以内容版本 URL 关联商城商品；不再逐个移入 Git 或改前端代码。
- 动态框属于单独商品等级，需先确认动效方案，同时交付静态备用图。

## 7. 图片验收

头像框按最终 PNG 文件直接验收，不依赖游戏页面。可使用 [头像框本地自检页](avatar-frame-preview.html) 辅助读取像素，但它不是必需交付物。必须检查：

- 文件格式、画布尺寸和文件大小。
- 四边 8 px 外边距是否透明。
- 除框体本身外，所有区域是否真实透明；没有底图、示例头像、棋盘格或透明度不足的色块。
- 可见像素是否全部在 512 × 512 画布内。

坐标检查通过后仍需直接查看成图确认以下项目：

- [ ] 38 px 时不看名称也能区分该主题。
- [ ] 框体完整覆盖在示例头像上方，没有被头像图片反压，也没有被人工裁掉的顶部、底座或内沿。
- [ ] 数字、字母、徽记、徽章和人物主体保持自然纵横比。
- [ ] 上方两个道具标记出现时，主题仍可识别。
- [ ] 框体与昵称之间至少有清晰视觉间隔。
- [ ] 无整圈刺眼白光、脏边、黑底或半透明方块。
- [ ] 四角没有被裁切，缩小时没有破碎锯齿。
- [ ] 浅色、深色、牌桌绿色背景均清楚。
- [ ] 文件名、`theme-id` 和设计说明一致。

## 8. 可直接复制的委托简报
